# Minimal Progress Note

`PROGRESS.md` is an optional resume note, not an assessment ledger. Update it only when something changes that affects the next session. Usually 5–10 lines is enough.

```md
# Progress: {topic}
- Source anchor: {source/notebook + heading or cell ID}
- Current task: {one learner-chosen build/application/performance result}
- Evidence: {what the learner actually produced; link if useful; help given}
- Unresolved: {specific blocker or unknown; omit if none}
- Next action: {one concrete action at the source anchor}
- Revisit: {one important earlier idea to reuse in later work; optional}
```

## Rules

- Keep the agreed contract, source ordering, and stable preferences in `NOTES.md`; do not duplicate them here.
- Evidence must distinguish learner-authored work from copied or AI-authored material. State whether it was unaided, with hints, following a demonstration, or reported but unobserved. “Done” is not evidence of understanding.
- No mandatory concept table, exercise log, numerical grade, state taxonomy, review schedule, or learning record per concept. Ordinary work supplies the evidence; a separate quiz is not required.
- Preserve unresolved gaps without blocking a learner-requested skip. Unknown is not the same as failed.
- Reuse important earlier ideas inside the current task when possible. Do not impose review batches on return; ask before a separate review session.
- If formal state labels are requested or genuinely useful, read [ASSESSMENT-FORMAT.md](./ASSESSMENT-FORMAT.md) before assigning them. Retain the same honest evidence standard without expanding the default note into a ledger.
- On return, read this and `NOTES.md`, locate the source anchor, and continue. Consult older files only when relevant; do not restart the course or run an intake battery.
- Do not rewrite unchanged state or copy evidence into multiple files for completeness.
