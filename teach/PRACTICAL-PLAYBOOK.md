# Universal practical teaching playbook

Choose a domain-specific loop, not a fixed lab template.

- Programming: explain a concept → show a minimal example → learner predicts/edits code → run tests → debug → apply to a new case.
- Electronics/RFIC: physical intuition → derive/predict → simulate → inspect traces and KPIs → diagnose → change one parameter.
- Embedded/HDL: define behavior → draw state/timing expectations → implement → testbench/hardware → inspect failure → refine.
- Mathematics: interpret → demonstrate reasoning → learner solves → check independently → vary assumptions.
- CAD/creative tools: explain objective → demonstrate operation → learner creates → inspect artifact → revise.
- General software: explain task and UI → demonstrate one action → learner repeats/adapts → inspect result → troubleshoot.
- Research/writing: evaluate source/example → learner constructs argument or draft → critique evidence → revise.

In every domain, give more explanation when the learner is new, one practical step at a time when they are executing, and honest feedback based on what they actually produced.
